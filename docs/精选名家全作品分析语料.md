# 精选名家全作品分析语料

项目采用两层语料，二者用途不同，不应互相覆盖。

- `data/poems.json` 是 canonical 展示层，继续服务诗页、原文、译注、赏析、事实卡、编年证据与 Agent。
- `data/analysis/famous_poets_full.jsonl.gz` 是 `analysis_full` 分析层，只覆盖 canonical 名册中的 88 位精选名家，用于色彩、数字夸张、人称孤独、声音、情感等状态统计。

全作品层由 `chinese-poetry/chinese-poetry` 的数值分片构建，固定上游提交为 `b8594f81a89752241442f2ce267d6f66f96704ee`，并保留 canonical 正文。当前产物为 80,893 条去重作品、88 位诗人；每条记录保留完整正文、正文哈希、人物时期、作品朝代、来源文件、来源提交和 canonical 匹配信息。上游项目采用 MIT License。

作品身份以规范化但不改字的正文计算；OpenCC 转换结果只参与候选去重，不再作为 canonical 身份。旧构建曾把 19 组转换后相同、原文实际不同的 canonical 正文折叠在一起，新构建会分别保留，并以 manifest 中的动态记录数为最终口径。

## 构建与校验

先准备稀疏检出的上游目录：

```bash
git clone --filter=blob:none --no-checkout https://github.com/chinese-poetry/chinese-poetry.git .cache/chinese-poetry
git -C .cache/chinese-poetry sparse-checkout set 全唐诗 宋词
git -C .cache/chinese-poetry checkout b8594f81a89752241442f2ce267d6f66f96704ee
```

安装依赖并构建：

```bash
python -m pip install -r requirements.txt
python tools/famous_poet_corpus.py build
python tools/famous_poet_corpus.py check
```

构建器只读取以下数值分片，避免把说明、排行榜或年份派生文件混入正文：

- `全唐诗/poet.tang.<数字>.json`
- `全唐诗/poet.song.<数字>.json`
- `宋词/ci.song.<数字>.json`

`data/analysis/famous_poets_full_manifest.json` 记录上游提交、输入文件清单、canonical SHA-256、压缩产物 SHA-256、记录数、去重数、朝代与诗人分布。统计 loader 会在使用全作品层前核对 manifest；canonical 或压缩产物变化而未重建时应直接失败，不能静默读取旧数据。

## 统计重建

```bash
python data/stylometry/scan_color.py
python data/stylometry/scan_number.py
python data/stylometry/scan_solitude.py
python data/stylometry/scan_sound.py
python tools/build_emotion_profiles.py
```

统计输出会写入 `corpus_source`、`corpus_path`、逐作品 `work_id`、`canonical_gushiwen_id` 和兼容字段 `body_hash`。全作品层不存在时允许回退 canonical；全作品层存在但校验失败时不会回退。

## 解释边界

“全作品”表示上述固定提交中、能与 88 位精选名家精确映射且通过时期过滤的完整正文集合，不宣称覆盖所有传世异文，也不等同于权威校勘本。重复正文按“诗人 + 规范化正文哈希”合并；同题异文保留为不同作品。消费者应以 `work_id` 作为分析层作品主键，canonical 页面优先用 `source_poem_id` 对应 `canonical_gushiwen_id`；`body_hash` 只是兼容性的内容签名，不能单独当作作品唯一键，更不能只按作者与标题关联。
