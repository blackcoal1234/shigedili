## 一、任务概述

把「诗行万里」唐宋诗歌知识库中由 `gpt-5.4-mini` 自动生成的诗歌导读卡（`poem_guide`），逐批替换为由你**亲自撰写**的高质量导读卡。每批 30 首。

- **进行中**：`batch_055` – `batch_057` 的分片已写完（18 个 fragment 都在），但**尚未组装、尚未入库**

## 二、项目背景

「诗行万里」唐宋诗歌数字人文项目：88 位诗人，19,418 首诗。知识库含 poems 表 + analyses 表（kind=`poem_guide` 即导读卡）。三层事实体系：`verified`（人工核验）/ `promoted_by_rule`（规则晋级）/ `promoted_ai_assisted`（AI 辅助放宽）。部分诗人为**零事实诗人**（本库无任何核验条目）：**上官仪、卢纶、欧阳炯、聂夷中**。

## 三、每张导读卡写作规范

```json
{ "poet": "李白", "title": "望庐山瀑布",
  "summary": "紫烟银瀑一望间，把山写成了天上的事。",
  "guide": "先看颜色和光：日照香炉，紫烟蒸腾……（150-240字向导口吻赏析）",
  "origin": "通说此诗作于开元十三年（725）前后……（80-160字，必须「通说」开头）",
  "confidence": 0.95 }
```

| 字段 | 要求 |
|------|------|
| `poet` / `title` | 与 poems 表**逐字一致**（含异体、空格、标点；库内错别字不要擅自纠正） |
| `summary` | ≤30 字，一句话抓住核心画面/情绪，要有人味 |
| `guide` | 150–240 字，**向导口吻**（站在读者身边低声讲解），先画面后手法；禁"这首诗表达了""通过……抒发了"等模板句与机器腔；禁出现字段名；不复述 origin 的考据 |
| `origin` | 80–160 字，**必须以「通说」开头**；写背景与作年/作地；禁虚构史料、页码、日期 |
| `confidence` | 0.5–0.99（名篇 0.85–0.95、常见 0.7–0.85、冷门 0.5–0.7） |

**证据引用**：若旧卡 evidence 非空（verified_fact 文本），origin 必须提及且**原文照用**，如"库内核验系年约726年（AI辅助放宽）"或"库内核验系年约837年、作于洛阳（规则晋级）"；evidence 为空则写"本库暂无核验系年与作地条目"。**零事实诗人**（上官仪/卢纶/欧阳炯/聂夷中）origin 一律写"本库暂无核验条目"，confidence 给 0.5。

## 四、执行边界与硬约束

### 1. 工作边界
- 本任务只替换 `analyses.kind='poem_guide'` 中由 `gpt-5.4-mini` 生成的导读卡；不要新增诗、改诗文、改诗人名、改 facts、改 schema。
- 写作阶段只允许创建/覆盖本轮目标 fragment：`data/assistant_guides/fragments/batch_0XX_partP.json`。除修正本轮 fragment 的明显格式/长度错误外，不改历史 fragment。
- 组装阶段只生成本轮 `data/assistant_guides/batch_0XX.json`；入库只能通过 `tools/insert_assistant_guides.py`，不要手写 SQL 直接更新主库。
- `output/assets/knowledge/poetry_knowledge.sqlite3` 是主知识库。入库前只读，入库时串行执行脚本；不要让多个插入脚本并发写同一个数据库。
- `data/reviewed/`、`tools/insert_assistant_guides.py`、`tmp/select_batches.py`、`tmp/assemble_batch.py` 的逻辑默认不动。除非脚本本身报出确定 bug，否则不要顺手改工具链。

### 2. 并发边界
- 并发只用于"选批后撰写 fragment"阶段；选批、组装、插入、验收必须由主代理串行收口。
- 一个子代理只负责一个 `(batch, part)`，只写一个目标文件；不得两个子代理写同一个 fragment，也不得让子代理跨分片补写。
- 每个子代理必须先打印自己负责的 5 首正文、evidence、origin_old，再动笔；不得只凭题名或旧卡写。
- 子代理返回为空、执行中断或未落盘时，只重跑缺失 fragment；不要整批重跑已经存在且自检通过的 fragment。
- 若平台并发槽不足 30 个，仍保持"每波 5 批"的批次定义，按 15+15 或 18+12 分两轮投递；不得因此改成重叠选批。

### 3. 内容红线
- 不调用外部 LLM API，不联网查资料补史实，不编造出处、页码、精确日期、作地。
- 不复制旧卡，不把旧卡做同义改写；旧卡只作为 origin_old 的风险参照。
- evidence 非空时必须原文照用到 origin；evidence 为空时不得写成已有核验。
- "通说"只是写作口径，不等于史实确认；不要写"史载确证""必作于"等确定性过强表述。
- 零事实诗人一律写"本库暂无核验条目"，confidence 固定 0.5，不做例外。

## 六、后续批次标准工作流（每波 5 批 × 6 分片 = 30 并发）

### 第 1 步：一次性选 5 个互不重叠的批次（已写脚本，自动排除已完成）
```powershell
python tmp/select_batches.py 058 5
```
> 生成 `tmp/_b058.json` + `tmp/_b058_info.json` 等，顺延到 `tmp/_b062_info.json`（每个 info 含 body/evidence/origin_old）。`select_batches.py` 内部维护排除集，五批不会重复。

### 第 2 步：并发撰写
用 **Task/subagent 并发**：每个子代理负责一批的 1 个分片（5 首），一批 6 个分片，一**波并行 5 批 = 30 个子代理**。给每个子代理的提示词必须包含：

1. 工作目录 `D:\game存档\诗行万里2\诗行万里`；负责 `tmp/_b0XX_info.json` 索引 `a–b`（分片 p 负责 `(p-1)*5 .. p*5-1`，含诗题清单）
2. 数据打印命令（PowerShell 引号注意）：
   `python -c "import json,io,sys; sys.stdout=io.TextIOWrapper(sys.stdout.buffer,encoding='utf-8'); d=json.load(open('tmp/_b0XX_info.json',encoding='utf-8')); [print('====',i,x['poet'],x['title'],'\n',x['body'],'\nEVIDENCE:',x['evidence'],'\nOLD:',x['origin_old'],'\n') for i,x in enumerate(d) if A<=i<=B]"`
3. §三 的完整写作规范（逐字给，别省略）
4. 输出写入 `data/assistant_guides/fragments/batch_0XX_partP.json`，格式：
   `{"batch":"batch_0XX_partP","author":"opencode 并发子代理逐首撰写","policy":"summary≤30字；guide 150-240字向导口吻；origin 80-160字以「通说」开头；置信为撰写者自评","items":[...5条...]}`
   用 `Python open(...,'w',encoding='utf-8')` 写入
5. 自检命令（含后报错修正）：
   `python -c "import json,io,sys; sys.stdout=io.TextIOWrapper(sys.stdout.buffer,encoding='utf-8'); d=json.load(open('data/assistant_guides/fragments/batch_0XX_partP.json',encoding='utf-8')); errs=[]; [errs.append(f'{i}:s{len(it[\"summary\"])}') for i,it in enumerate(d['items']) if len(it['summary'])>30]; [errs.append(f'{i}:g{len(it[\"guide\"])}') for i,it in enumerate(d['items']) if not (150<=len(it['guide'])<=240)]; [errs.append(f'{i}:o{len(it[\"origin\"])}') for i,it in enumerate(d['items']) if not (80<=len(it['origin'])<=160)]; [errs.append(f'{i}:ostart') for i,it in enumerate(d['items']) if not it['origin'].startswith('通说')]; [errs.append(f'{i}:c') for i,it in enumerate(d['items']) if not (0.5<=it['confidence']<=0.99)]; print('ERRS:',errs if errs else 'ALL OK')"`
6. 红线：遵守 §四；不调用外部 LLM API；不改动 `data/reviewed/` 及既有数据；不把「通说」写成「史实」；不编造出处页码日期；不复制旧卡
7. 若该分片含零事实诗人（见上表清单），明确告知对应诗题：origin 写"本库暂无核验条目"、confidence 0.5

### 第 3 步：收尾（每波后）
- 先检查分片齐全（把 `START` 改成本波首批号）：`python -c "import os; START=58; batches=[f'{n:03d}' for n in range(START,START+5)]; print([f'batch_{n}_part{p}' for n in batches for p in range(1,7) if not os.path.exists(f'data/assistant_guides/fragments/batch_{n}_part{p}.json')])"`
- **子代理偶发"执行中断/返回为空却没写文件"**：核对缺失分片后用同样提示词重跑即可
- 组装：`python tmp/assemble_batch.py 058`（顺延 059、060、061、062）
- 插入（**逐批串行执行，超时给 600000**）：`python tools/insert_assistant_guides.py --batch data/assistant_guides/batch_0XX.json`
- 验收：`python tmp/check_count.py`

## 七、经验与坑（务必记住）

1. **插入脚本默认 120s 会超时被杀**（末尾 validate_database 慢）。超时前 commit 与 FTS 重建已完成、数据是好的；但**请始终给足超时**，避免误判。
2. **零事实诗人**：卢纶出现频率很高（剩余 63 首），每批都可能遇到；上官仪、欧阳炯、聂夷中偶发。
3. **题名异体/错别字**：以 poems 表实际字串为准，选中后如插入提示"不在库"，用 `SELECT poet,title FROM poems WHERE poet=?` 查库内真实题名再改批内 title（已有先例：叶梦得《临江仙·…南山绝**项**…》库内是「绝项」非「绝顶」）。
4. 每批 30 首里若有组诗/古文/赋（如《种树郭橐驼传》《师说》《小石潭记》《代李敬业传檄天下文》《超然台记》），guide 讲其文章结构、手法、主旨即可，仍须 150–240 字；极短残句（如《句》《太常乐章》），guide 从句意/语境/作者风格展开但不注水。
5. 一旦插入成功，`select_batches.py` 会自动排除该诗，不会重复选。
6. 写分片时**先打印全诗正文再动笔**，杜绝凭诗题瞎编内容。
